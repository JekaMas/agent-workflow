# Design

Shared source owns general procedures and validator algorithms; consumer JSON selects publication roots and packaging policy. Existing names remain thin adapters so domain routes survive. Fixed consumer budgets, flat-reference and implicit-invocation policies do not become universal defaults.

Bootstrap detects checked-in/on-disk Go and Rust module manifests while excluding vendor/build/shared trees and following no links. Detection is a proposal, never toolchain qualification or product command execution. Explicit profiles win. Existing OpenSpec setups require a prepared migration plan binding prior files, proposed outputs, repository and source revision; inspect custom config/instructions before applying. Only listed outputs change. Active specs/changes are preserved; no force bypass or framework reinstall.

Validate new/managed/custom adopters, stale-plan rejection, unchanged custom artifacts, missing references, publication failures and both client routes. Existing product approvals remain local. Evidence and coverage belong here, not another consumer task list.

## Extraction-equivalence repair

Restore original per-run effective-disposition and programmatic independent-model assertions; directed witnesses may satisfy rare cases within a run. Keep evidence in the existing record, not a universal new manifest. Restore failed-direct-attempt/unknown-owner activation, discrepancy coverage, per-fix confirmation/admissibility and instruction-effectiveness diagnosis. Retain the previously requested same-change authorized repair loop; diagnosis-only authority remains read-only. Restore one conflict slice at a time and original top-down dependency order until validated or explicitly blocked.

Generic workflow checks must invoke the same consumer packaging and publication engines already used by Smart Example. Bootstrap generates explicit consumer policy files and docs invoke both commands; preserve every exit and require intentional new sources staged before publication checking. Existing custom Smart Example wrappers/policies remain the local selection owners. No new verifier, CI job, provider call or product implementation is required.

Exact relocation, minor adaptation and substantive prior additions are distinguished in extraction-equivalence.md. Earlier API-provider/adoption work is retained as explicitly requested functionality, not mislabeled a byte-preserving move. The initial shared baseline's unavailable pre-extraction Git source remains a provenance limit, not a fabricated equivalence pass.
