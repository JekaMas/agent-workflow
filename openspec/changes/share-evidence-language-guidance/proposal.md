# Proposal

## Why
Reusable testing, review and language procedures remain embedded in a consumer. New repositories get less guidance, while generic workflow requirements are recorded only in that consumer's migration.

## What Changes
- Establish the existing portable-workflow, adaptive-development-workflow and assurance-routing specifications in this shared repository.
- Extract conditional verification, Go and Rust references into existing shared skills.
- Replace consumer copies with links or adapters preserving domain contracts and approvals.
- Remove separate-stage handoffs from authorized implementation review/repair.

## Capabilities
### New Capabilities
- `conditional-engineering-guidance`: portable, conditional engineering references with preserved consumer policies.
### Modified Capabilities
None. Portable-workflow is transferred as an existing baseline, not changed behavior.

## Impact
Shared skills and their reference validation; Smart Example skill adapters and maintenance documentation. No product code, dependencies, CI, provider calls or permission changes.
