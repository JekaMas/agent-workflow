# Personal development defaults

Follow runtime precedence and all applicable project instructions. Resolve the
actual repository/worktree before repository-aware tools or project skills.
For substantial development, use `sdd-workflow`: prefer the repository's existing
workflow and pinned procedures. Use `sdd-maintenance` for workflow changes.
Small edits need proportionate inspection, not automatic setup or planning.

Preserve exact requirements and useful project knowledge. Do not silently weaken
contracts, change accepted inputs or add assumptions to claim equivalence or DONE.
Report material contradictions and missing evidence; complete independent authorized
work before asking. Continue through authorized implementation, review, repair and
revalidation; retain concise resume notes in the current task's canonical record.

Select tools and references by the actual question. Repository/source inspection
is not permission to execute recipes. Delegation, installs, external calls and
publication follow current user/runtime authority, never these defaults. Do not
claim semantic, operational or independent evidence that was not obtained.
