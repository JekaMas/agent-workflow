# Adaptive delivery

## Start and plan

Identify outcome, scope, existing related requirements, active changes and exact
worktree/revision. Preserve unrelated work. Resume the matching intent or create
a change using the installed schema. Routine edits without durable planning need
may proceed directly with proportionate inspection.

Read native artifact instructions and dependency context as needed. Keep intent
in proposal, observable requirements in specs, decisions/risks in design and one
authoritative task list. Link bounded evidence. Artifact readiness is not product
completion or approval. Challenge consequential specifications against ambiguous
terms, incompatible requirements, missing cases and plausible wrong behavior.

Detail the next useful increment, keeping later work coarse and the full requested
outcome visible. Record objective, requirements, dependencies, important uncertainty,
work and needed evidence only where useful. Investigation, prototype, model and
harness increments are valid. No fixed iteration count or mandatory tiny slices.

## Execute and adapt

Follow native apply guidance and selected tasks. Inspect results at meaningful
boundaries and update affected specs/design/tasks. Refine approach within intent;
a materially different intent or independently deliverable scope needs a separate
change. Acceptance and authority cannot silently weaken. Keep concise resume
notes with completed outcomes, remaining criteria, evidence and next action.

- CONTINUE when useful authorized work remains and the next action is clear.
- REPLAN when evidence changes the approach or exposes missing work within scope.
- ASK for material ambiguity, incompatible requirements, consequential irreversible
  decisions or missing authority, after independent authorized work. Present the
  smallest concrete question, recommendation and consequences.
- BLOCKED means a required dependency/check/decision is unavailable after reasonable
  investigation. Record witness, affected criteria and exact unblock action;
  continue independent work. A timeout or exhausted budget is not success.
- DONE requires the requested outcome, matching artifacts, final relevant required
  evidence, appropriate diff/behavior inspection and resolved material findings.
  Report acceptance-consistent limitations and stop optional polishing. A verified
  already-satisfied outcome needs no artificial patch.

## Review and finish

Review actual code and evidence against requirements; repair in-scope findings and
rerun affected checks. Preserve review-only scope. Debug/review activities return
to the implementation task rather than ending it prematurely. Self-review is not
independent review. If attempts stop yielding information, change the discriminator
or record the blocker rather than repeat unchanged work.

Task checkboxes, structural validation, a clean review and archive do not alone
establish DONE. Preserve required real-boundary evidence; separate local completion
from external approval/deployment. Archive only under task authority after completion,
using installed instructions and inspecting resulting spec changes. Leaving a
completed change unarchived for review is valid.
