# Shared workflow maintenance

Prefer a repository's maintenance skill when available. Otherwise resolve this
skill's real package directory and read `docs/adoption.md` and the relevant part of
`docs/maintenance.md`. Inventory existing instruction owners before changing them.
Use bootstrap repo preview/apply for new or managed repositories; manifests propose language routes. For an existing spec-driven setup, use prepare with a review directory, preserve useful custom rules in project references, then apply the explicitly reviewed migration plan. Refuse stale plans and retain active changes. Other schemas and output aliases need a specific migration, never silent replacement.
Keep project knowledge local, use exact package revisions, and qualify consumer
behavior and failure paths. Global installation is separate from repository setup
and requires user authority. Preserve backups and report restart/discovery limits.
